 MODERATE - Bug 2. Loaded configuration values are not normalised
            (still open from notes_009 Fix 2)
------------------------------------------------------------------------------
 File:    scriptorium.py
 Functions / methods:
  load_config 166-190
  build_system_prompt 252-280 (MODE_INSTRUCTIONS[mode], STRENGTH_INSTRUCTIONS)
  SettingsDialog.__init__ 744-752 (BooleanVar)
  Scriptorium._build_toolbar 841-860; process 1044-1047

 Failure point
  load_config only insists that the root is a dict, then cfg.update(loaded).
  A hand-edited or truncated file may contain "default_mode": "Rewrite",
  "protect_placeholders": "false", or "privacy_ack": "false".

  (i) process() passes mode_var / strength_var straight into
      build_system_prompt, which indexes MODE_INSTRUCTIONS[mode]. An
      unsupported mode raises KeyError in the worker and surfaces as
      "Unexpected error: 'Rewrite'".

  (ii) tk.BooleanVar(value=...) and later bool(self.protect_var.get()) do not
       treat the JSON string "false" as False. A stringy privacy_ack of
       "false" is truthy, so the cloud privacy notice is skipped.

  (iii) Opening Settings with a non-Boolean protect_placeholders can raise
        TclError in BooleanVar and prevent Settings from opening at all.

 Impact
  A recoverable config typo becomes a failed Process, a skipped privacy
  notice, or a broken Settings dialog. API keys and free-form model names
  should be left untouched; only enumerations and booleans need clamping.

------------------------------------------------------------------------------
 MODERATE - Bug 4. TimeoutError is not caught on either backend (new)
------------------------------------------------------------------------------
 File:    scriptorium.py
 Functions: call_anthropic 397-408; call_ollama 441-453

 Failure point
  urlopen(..., timeout=120) / timeout=300. From Python 3.10 (the README
  minimum) a timed-out urllib request raises TimeoutError, which is an
  OSError but not a urllib.error.URLError. The existing except tuples are
  HTTPError, URLError, and (Claude only) JSONDecodeError. TimeoutError
  therefore falls through to process()'s generic Exception handler:
  "Unexpected error: timed out".

  list_ollama_models already includes OSError, so Detect is covered.

 Impact
  A slow Claude or Ollama call surfaces as an unexpected error instead of a
  clear timeout. Same user-visible class of failure as Bug 3.

------------------------------------------------------------------------------
 MODERATE - Bug 5. Status bar and run_backend disagree on an unknown backend
            (new; privacy / data-consistency)
------------------------------------------------------------------------------
 File:    scriptorium.py
 Functions / methods:
  run_backend 460-463
  Scriptorium._refresh_status 954-961
  Scriptorium._maybe_show_privacy_notice 968-978

 Failure point
  run_backend treats anything other than the exact string "ollama" as Claude:
      if cfg.get("backend") == "ollama": return call_ollama(...)
      return call_anthropic(...)

  _refresh_status treats anything other than the exact string "anthropic" as
  local Ollama:
      if backend == "anthropic":  # "text is sent to Anthropic"
      else:                       # "stays on this machine"

  _maybe_show_privacy_notice only runs when backend == "anthropic".

  So a hand-edited "Ollama", "local", "", or null:
    * status bar claims the text stays on this machine;
    * the privacy notice is not shown;
    * run_backend sends the text to Anthropic (and will then fail the API
      key check, or worse, succeed if a key is present).

  Settings always writes the two canonical strings, so a UI-only session is
  fine. The mismatch is real for a typed JSON file, a partial merge, or any
  future key such as "claude".

 Impact
  The UI can lie about whether text leaves the machine. Combined with Bug 2
  this is the remaining data-consistency hole in configuration.

------------------------------------------------------------------------------
 MODERATE - Bug 6. Worker calls Tk after() after the window is destroyed
            (still open from notes_009 Finding 5; more visible now the app
            is a windowed .exe)
------------------------------------------------------------------------------
 File:    scriptorium.py
 Class:   Scriptorium
 Methods: process.worker 1050-1061; _claim_request 1003-1004; _on_close 1285-1288

 Failure point
  _on_close invalidates in-flight work and destroy()s the window. The daemon
  worker, when urlopen returns, still executes:
      self.after(0, self._on_success, request_id, original, ph_map, result)
  (or _on_error). _claim_request's winfo_exists() guard only runs if after()
  successfully queued the callback. after() itself on a destroyed interpreter
  raises tk.TclError on the worker thread.

  scriptorium.spec sets console=False and disable_windowed_traceback=False.
  An unhandled exception on that thread can therefore produce a PyInstaller
  traceback dialog after the user has already closed the app.

 Impact
  Close-while-processing is the realistic case (Claude timeout is 120s). Not
  data corruption, but a post-quit crash dialog on the packaged build.

### Fix 1 - Run Detect off the Tk thread (Bug 1)

Replace SettingsDialog._detect_models (lines 767-780). Keep list_ollama_models

    def _detect_models(self):
        """Ask Ollama which models are installed, without freezing Settings."""
        self.detect_btn.configure(state="disabled")
        self.ollama_status.configure(text="Detecting…")

        def worker():
            models = list_ollama_models()
            try:
                self.after(0, self._apply_detected_models, models)
            except tk.TclError:
                return

        threading.Thread(target=worker, daemon=True).start()

    def _apply_detected_models(self, models):
        """Populate the Ollama combobox on the Tk thread."""
        if not self.winfo_exists():
            return
        cloud = self.backend_var.get() == "anthropic"
        self.detect_btn.configure(state="disabled" if cloud else "normal")
        if not models:
            self.ollama_status.configure(
                text="No response from Ollama at localhost:11434 — is "
                     "'ollama serve' running?")
            return
        current = self.ollama_combo.get().strip()
        values = models if (current in models or not current) else [current] + models
        self.ollama_combo.configure(values=values)
        self.ollama_status.configure(text=f"Found {len(models)} model(s).")

    def normalise_config(cfg):
        """Return a copy whose typed preferences are known, supported values.

        Free-form fields (API key, model tags) are left unchanged. An
