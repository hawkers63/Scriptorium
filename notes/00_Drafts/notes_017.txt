1. UI/UX AUDIT & VISUAL HIERARCHY
--------------------------------------------------------------------------------

1.1 Overall
The shell is already a credible Windows 11 dark app: CTk dark/blue, 1180x760
default, 920x600 minimum, dual panes with uniform column weights. The two-row
action bar (comment at ~1748) correctly fixed the 13-button overlap. Live
word counts, presets, Softer/Stronger, Copy/Paste, and the tone picker are
in place.

What still reads as "utility" rather than "Win11 writing surface" is
inconsistent type, chrome that does not match between the two panes, a
toolbar that cannot wrap at 920px, a Working… state that only changes a
label, and a warning strip with no dismiss control.

1.2 Dual-pane typography (highest visual defect)
  Original  CTkTextbox, CTkFont(size=14), theme background (typically
            ~#2b2b2b), implicit CTk padding and inner scrollbar.
  Revised   tk.Text, ("Segoe UI", 12), background #1d1e1e, padx/pady 10,
            external CTkScrollbar, no spacing1/spacing3.

  Result: the right pane looks smaller, greyer, and more "code editor"
  than the left. Headers are CTkFont(weight="bold") with no size, so they
  follow the default 13px while body type disagrees. No line-height is
  set on either widget (spacing1/spacing3 unused). Horizontal rhythm is
  close (uniform="col", padx 6 gutter) but the inner padding of CTkTextbox
  vs tk.Text(padx=10) is not matched, so the first glyphs do not line up.

1.3 Diff highlighting & contrast
  Tokenisation is word / punctuation / whitespace (_tokenise). That is the
  right grain for copy-editing. Character-level diffs would spray colour
  across every letter of a British spelling change (organise/organize) and
  should stay off.

  Against pane background #1d1e1e (WCAG 2.x relative luminance):

    Body text  #dce4ee    13.03:1   AAA
    Changed    #4ec9b0     8.20:1   AAA (normal text)
    Deleted    #e06c75     5.23:1   AA  (only 0.73 above 4.5)

  Both colours pass AA as foreground-only. They still fail as *scan*
  colours: Clean view tints insertions with no fill, so a light paraphrase
  is easy to miss; Inline strikethrough is a 1px overstrike that thins out
  at 150–200% DPI. Deleted red is the tightest AA pair and will look muddy
  on a dim laptop panel.

  The amber banner #3a2f1a is not a text colour (1.27:1 vs pane bg — it is
  a fill). Body #dce4ee on #3a2f1a is 10.23:1, so legibility is fine; the
  problem is chrome (looks like a dirty slab, no heading weight, no close).

1.4 Toolbar & action bar
  Toolbar is a single grid row: Mode, Strength, Role, Tone button (150px),
  Preset (145px), Settings. Labels use padx=(20, 4) between groups. At
  1180px this is comfortable. At 920px the row cannot wrap (no row 1, no
  grid_columnconfigure on the control cells) so the Preset/Settings pair
  is clipped or stacked over Role/Tone. Settings sits in column 11 with a
  spacer in column 10 — good — but the left cluster has no shrink policy.

  Action bar row 1 (review): Process 100, − Softer 80, + Stronger 90,
  Accept 110, Reject 90, Copy revision 120, Copy summary 110, Undo 80.
  Sum of widths = 780px plus ~40px padx ≈ 820px. Tight at 920px but should
  fit. Row 2 (clipboard/file) is sparse and left/right packed — the empty
  middle is fine, but the two rows do not share a visual baseline (row 1
  pady (8,4), row 2 pady (0,8), no separator).

  Accept green #2f7d4f / hover #276a43 is the only filled accent besides
  Process blue. Softer uses a Unicode minus "−" which is good; the rest of
  the bar is gray30, so review actions other than Accept/Process compete
  equally with Undo.

1.5 Interactive states
  _set_busy (~1952) sets Process to "Working…" and disables Process,
  Accept, Softer, Stronger. No pulse, no progress bar, no animated
  ellipsis, no status-bar throbber. The status line gets a static
  "contacting the model…" string. On a 30-second Ollama call the UI looks
  frozen aside from that label.

  No CTk tooltips anywhere (scan: zero "tooltip" hits). Keyboard: Ctrl+Enter
  Process, Ctrl+I Import, Ctrl+S Export. No Escape on dialogs. No visible
  shortcut on Process any more (the old "Process  (Ctrl+Enter)" label was
  shortened to "Process").

1.6 Ambiguity banner
  CTkTextbox height=64, fg_color="#3a2f1a", packed before the status bar,
  state=disabled. Always titled "⚠ Ambiguities flagged…" even when the
  list is placeholder or letter-convention notices. No dismiss control;
  pack_forget only when the next result has an empty list. Disabled
  textbox blocks selection on some CTk versions, so users cannot copy a
  flagged line.

1.7 Dialogs
  TonePickerDialog 420x540, not resizable, transient+grab_set, scrollable
  checkbox list. No Escape, no WM_DELETE_WINDOW protocol (title-bar X
  still works via default destroy). No after_idle positioning — Tk places
  it on the current screen, which on a multi-monitor setup can open on
  the primary while Scriptorium sits on the secondary. Limit feedback uses
  a blocking messagebox.showinfo rather than the status_label already on
  the dialog.

  SettingsDialog 520x780, not resizable. 780px is taller than the app
  minimum height (600) and will clip on a 1080p laptop at 150% DPI
  (effective ~720px). Content is packed, not in a CTkScrollableFrame, so
  there is no overflow. Checkboxes wrap long British copy and misalign
  the tick column. No Escape. Save/Cancel are in a bottom pack(side=
  "bottom") row which can overlap the last checkbox if the window manager
  shrinks the dialog. Detect is already off-thread (good).

  British English in chrome is generally sound (minimise, colour in copy).
  Backend segmented values are still "anthropic" / "ollama" (internal ids
  shown to the user). Prefer "Claude" / "Ollama".

### 3.2 Centre a dialog on its parent
Insert as a module-level helper above TonePickerDialog (~1213).

def position_over_parent(window, master, width, height):
    """Place a modal on the same monitor as its parent, centred.

    Uses the parent's current geometry so a secondary-display session
    does not open Settings on the primary screen.
    """
    window.update_idletasks()
    try:
        px = master.winfo_rootx()
        py = master.winfo_rooty()
        pw = master.winfo_width()
        ph = master.winfo_height()
    except tk.TclError:
        return
    x = px + max(0, (pw - width) // 2)
    y = py + max(0, (ph - height) // 2)
    window.geometry(f"{width}x{height}+{x}+{y}")


def bind_dialog_chrome(window, on_close):
    """Escape and the title-bar close box both run on_close."""
    window.bind("<Escape>", lambda _e: on_close())
    window.protocol("WM_DELETE_WINDOW", on_close)

### 3.4 Working… pulse + indeterminate bar
Insert on Scriptorium, next to _set_busy (~1952). Requires a progress bar
created in _build_actionbar.

    def _set_busy(self, flag):
        """Disable destructive actions and show determinate-looking motion."""
        self.busy = flag
        self.process_btn.configure(
            text="Working…" if flag else "Process",
            state="disabled" if flag else "normal")
        for btn in (self.accept_btn, self.softer_btn, self.stronger_btn):
            btn.configure(state="disabled" if flag else "normal")
        if flag:
            self.progress.pack(fill="x", padx=12, pady=(0, 4),
                               before=self.status)
            self.progress.start()
            self._pulse_job = self.after(400, self._pulse_process)
        else:
            if getattr(self, "_pulse_job", None):
                self.after_cancel(self._pulse_job)
                self._pulse_job = None
            self.process_btn.configure(fg_color=["#3a7ebf", "#1f6aa5"])
            self.progress.stop()
            self.progress.pack_forget()

    def _pulse_process(self):
        """Alternate Process blue so a long Ollama call still feels alive."""
        if not self.busy or not self.winfo_exists():
            return
        current = self.process_btn.cget("fg_color")
        # CTk may return a string or a (light, dark) pair.
        dark = current[1] if isinstance(current, (list, tuple)) else current
        nxt = "#144870" if dark != "#144870" else "#1f6aa5"
        self.process_btn.configure(fg_color=nxt)
        self._pulse_job = self.after(400, self._pulse_process)

In _build_actionbar, after bar2 is packed (~1796):

                                           height=4)
        # packed on demand from _set_busy()

                               padx=10, pady=8)
        ctk.CTkButton(
            self.notice_frame, text="Dismiss", width=80, fg_color="gray30",
            command=lambda: self.notice_frame.pack_forget()
        ).pack(side="right", padx=8, pady=8)

    def _show_ambiguities(self, items):
        """Show model ambiguities and local notices in a dismissible banner."""
        if not items:
            self.notice_frame.pack_forget()
            return
        title = "Ambiguities flagged (not silently changed)"
        body = "\n".join(f"• {a}" for a in items)
        self.notice_label.configure(text=f"{title}\n{body}")
        if not self.notice_frame.winfo_ismapped():
            self.notice_frame.pack(fill="x", padx=12, pady=(0, 4),
                                   before=self.status)
