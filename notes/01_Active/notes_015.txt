1. EXECUTIVE SUMMARY & CODEBASE HEALTH ASSESSMENT
--------------------------------------------------------------------------------
A comprehensive, read-only static analysis was conducted across the Scriptorium
codebase located in C:\Scriptorium\.

The core application (scriptorium.py, v2.5, 2,276 lines) exhibits sound 
architectural discipline. Standard library modules (urllib.request, json, difflib,
secrets, winreg, ctypes) are utilised effectively to keep runtime dependencies
exceptionally lean. CustomTkinter provides a modern Windows 11 interface, and
optional extras (python-docx, pystray, pillow) are cleanly decoupled with robust
feature-gating and fallback behaviour.

Key Findings Summary:
  * Asset Desynchronisation (High): The icon assets on disk (Scriptorium-256.ico
    and Scriptorium-96.ico) do not match the filenames hard-coded in
    scriptorium.py (icon/icon-96.png) and scriptorium.spec (icon/icon-96.ico,
    icon/icon-96.png). In source runs, attempting to minimise to the system tray
    fails due to a missing image file.
  * Window Identity (Moderate): The main application window does not call
    iconbitmap/iconphoto, leaving the generic Tk feather icon visible in the
    title bar, Alt+Tab switcher, and taskbar when executed from source.
  * Process Multiplicity (Moderate): Background tray execution allows duplicate
    instances to be spawned via Scriptorium.bat or HKCU Run autostart, causing
    duplicate tray icons and CustomTkinter DPI tracker collisions.
  * Settings Model Retention (Moderate / Suspicion S1 Confirmed): Configuring a
    custom Claude model ID in scriptorium_config.json results in silent
    replacement with ANTHROPIC_MODELS[0] when saving via SettingsDialog.
  * Caret Placement on Paste Replacement (Minor / Suspicion S2 Addressed):
    Replacing a highlighted selection in paste_original() can leave the insertion
    caret at the boundary of the prior selection on specific Tkinter configurations.
  * Encoding Handling in File Import (Minor): Files with UTF-8 BOM retain the
    byte-order mark (\ufeff) in text content, and non-UTF-8 Windows text files
    (CP1252) fail immediately rather than attempting standard Windows fallbacks.

Finding 1: Tray Icon Asset Missing & PyInstaller Spec Desynchronisation
Severity : HIGH
Location : scriptorium.py (_minimise_to_tray, line 2238)
           scriptorium.spec (lines 35, 85)
--------------------------------------------------------------------------------
Description:
On disk in C:\Scriptorium\icon\, only Scriptorium-256.ico and Scriptorium-96.ico
are present (icon-96.png and icon-96.ico were removed).
In scriptorium.py:
    image = PILImage.open(resource_path(os.path.join("icon", "icon-96.png")))
Because Pillow natively supports opening .ico files, referencing the non-existent
PNG causes an OSError in source runs, aborting tray minimisation. Furthermore,
scriptorium.spec bundles icon/icon-96.png in `datas` and sets `icon="icon/icon-96.ico"`,
which causes PyInstaller packaging to fail or omit the intended application icon.

--------------------------------------------------------------------------------
Finding 2: Application Window Title-Bar & Taskbar Brand Icon Omission
Severity : MODERATE
Location : scriptorium.py (Scriptorium.__init__, line 1459)
--------------------------------------------------------------------------------
Description:
Scriptorium never calls self.iconbitmap() during window initialisation. Running
via `python scriptorium.py` or `Scriptorium.bat` results in Windows displaying
the default Tcl/Tk feather glyph in the title bar, taskbar, and Alt+Tab switcher.
Applying the bundled .ico upon initialisation and after a brief delay (to prevent
CustomTkinter internal DPI hooks from overriding it) provides a native, branded
experience.

--------------------------------------------------------------------------------
Finding 3: Multiple Process Spawning & Duplicate Tray Icons
Severity : MODERATE
Location : scriptorium.py (main, line 2269)
--------------------------------------------------------------------------------
Description:
When Scriptorium is minimised to the notification area, subsequent launches
(via desktop shortcuts, batch files, or logon autostart) spawn independent
processes. This generates multiple tray icons and causes CustomTkinter appearance/DPI
state clashes. Using a named Windows mutex (Local\ScriptoriumSingleInstance) and
event (Local\ScriptoriumRestore) via standard library `ctypes` ensures second
launches restore the existing window and exit immediately.

--------------------------------------------------------------------------------
Finding 4: Custom Anthropic Model Overwrite on Settings Save (Suspicion S1)
Severity : MODERATE
Location : scriptorium.py (SettingsDialog.__init__, line 1280)
--------------------------------------------------------------------------------
Description:
In SettingsDialog, `self.model_var` is bound to a CTkOptionMenu initialised with
`values=ANTHROPIC_MODELS`. If a user specifies an alternative or newly released
model in scriptorium_config.json (e.g. "claude-3-7-sonnet-20250219"), the menu
omits it from the values list and CTkOptionMenu resets `model_var` to
ANTHROPIC_MODELS[0] on save, silently discarding custom configuration.

--------------------------------------------------------------------------------
Finding 5: Caret Placement on Selected Text Replacement in paste_original()
Severity : MINOR
Location : scriptorium.py (paste_original, lines 2093-2098)
--------------------------------------------------------------------------------
Description:
When replacing highlighted text in Original, `self.original_box.delete("sel.first",
"sel.last")` removes the characters, but if the selection was made backwards,
the insertion mark ("insert") can remain positioned at the trailing edge in
some Tk versions before inserting `incoming`. Explicitly querying the selection
range and setting the insertion mark to `sel.first` guarantees deterministic
placement.

--------------------------------------------------------------------------------
Finding 6: UTF-8 BOM Retention and CP1252 Fallback in import_file()
Severity : MINOR
Location : scriptorium.py (import_file, lines 2135-2151)
--------------------------------------------------------------------------------
Description:
`import_file()` opens plain text files using standard `utf-8`. If a file has a
UTF-8 Byte Order Mark, `\ufeff` is retained in the text buffer and transmitted
to the LLM backend. If `utf-8` decoding fails, the current except block attempts
`utf-8-sig`, which fails with the identical UnicodeDecodeError on non-UTF-8
files. Using `utf-8-sig` as the primary encoding automatically strips any BOM,
and falling back to `cp1252` accommodates common legacy Windows document files.

--------------------------------------------------------------------------------
Finding 7: SettingsDialog Missing Transient Window Relationship
Severity : MINOR
Location : scriptorium.py (SettingsDialog.__init__, line 1254)
--------------------------------------------------------------------------------
Description:
While `TonePickerDialog` sets `self.transient(master)`, `SettingsDialog` calls
`self.grab_set()` without declaring transience. On Windows, this allows the modal
dialogue to appear as an unlinked taskbar entity that can drop behind the parent
window during Alt+Tab switching.

--------------------------------------------------------------------------------
Finding 8: Revision Word Count Delta Computed Against Stale Original Buffer
Severity : MINOR
Location : scriptorium.py (_refresh_status, lines 1720-1724)
--------------------------------------------------------------------------------
Description:
In `_refresh_status()`, `delta = r_words - words` compares the revision word
count against the current text in `self.original_box`. If the user edits or
clears the Original pane while reviewing a revision, the displayed delta reflects
the modified buffer rather than `self._result_source` (the source text from which
the revision was actually generated).

```python
import ctypes

_MUTEX_NAME = "Local\\ScriptoriumSingleInstance"
_RESTORE_EVENT_NAME = "Local\\ScriptoriumRestore"
_mutex_handle = None
_ERROR_ALREADY_EXISTS = 183
_INFINITE = 0xFFFFFFFF


def _claim_single_instance():
    """Return True if this process successfully claimed the single-instance mutex.

    Returns False if another instance of Scriptorium is already active.
    The mutex handle is retained at module level to prevent garbage collection.
    """
    global _mutex_handle
    kernel32 = ctypes.WinDLL("kernel32", use_last_error=True)
    _mutex_handle = kernel32.CreateMutexW(None, False, _MUTEX_NAME)
    return ctypes.get_last_error() != _ERROR_ALREADY_EXISTS


def _signal_existing_instance():
    """Signal the active Scriptorium instance to restore its main window."""
    kernel32 = ctypes.WinDLL("kernel32", use_last_error=True)
    handle = kernel32.OpenEventW(0x00100002, False, _RESTORE_EVENT_NAME)  # EVENT_MODIFY_STATE
    if handle:
        kernel32.SetEvent(handle)
        kernel32.CloseHandle(handle)
```

```python
    def _start_restore_listener(self):
        """Start a background daemon thread to listen for single-instance restore signals."""
        kernel32 = ctypes.WinDLL("kernel32", use_last_error=True)
        self._restore_event = kernel32.CreateEventW(None, True, False, _RESTORE_EVENT_NAME)

        def _listener():
            while True:
                kernel32.WaitForSingleObject(self._restore_event, _INFINITE)
                kernel32.ResetEvent(self._restore_event)
                self._post_to_ui(self._bring_to_front)

        threading.Thread(target=_listener, daemon=True).start()

    def _bring_to_front(self):
        """Restore and raise the main application window whether hidden or minimised."""
        if self.tray_icon is not None:
            try:
                self.tray_icon.stop()
            except Exception:
                pass
            self._finish_tray_restore()
            return
        self.deiconify()
        self.lift()
        self.focus_force()
```

Feature 1: Copyable Change Summary
--------------------------------------------------------------------------------
Usability Rationale:
When editing formal letters, technical documentation, or client replies, authors
frequently need to provide a concise statement of modifications (e.g. for a
covering note, commit summary, or audit log). Scriptorium already leverages
`difflib.SequenceMatcher` for diff rendering; this feature computes a one-line
British English summary of word-level adjustments and enables one-click copying
to the clipboard.

Implementation:
1. Helper function `summarise_diff()`:
   File   : scriptorium.py
   Context: Module level, insert immediately after render_diff() (line 1011)

```python
def summarise_diff(original, revised):
    """Return a concise, one-line British English summary of text modifications.

    Analyses word-level inserts, deletions, and replacements using the same
    tokenisation as render_diff. Example outputs:
      '12 words inserted, 4 deleted, 3 replaced'
      'no wording changes'
    """
    a, b = _tokenise(original), _tokenise(revised)
    matcher = difflib.SequenceMatcher(None, a, b, autojunk=False)
    inserted = deleted = replaced = 0
    word_re = re.compile(r"\w", re.UNICODE)

    def count_words(tokens):
        return sum(1 for tok in tokens if word_re.search(tok))

    for tag, i1, i2, j1, j2 in matcher.get_opcodes():
        if tag == "insert":
            inserted += count_words(b[j1:j2])
        elif tag == "delete":
            deleted += count_words(a[i1:i2])
        elif tag == "replace":
            replaced += count_words(b[j1:j2])

    clauses = []
    if inserted:
        clauses.append(f"{inserted} word{'s' if inserted != 1 else ''} inserted")
    if deleted:
        clauses.append(f"{deleted} deleted")
    if replaced:
        clauses.append(f"{replaced} replaced")

    return ", ".join(clauses) if clauses else "no wording changes"
```

```python
    def _load_file_path(self, path):
        """Load document text into Original from a resolved file path (.txt, .md, .docx)."""
        if not path or not os.path.isfile(path):
            return
        ext = os.path.splitext(path)[1].lower()
        if ext not in (".txt", ".md", ".docx"):
            self._refresh_status(f"unsupported file format: {ext}")
            return

        if ext == ".docx":
            try:
                content = read_docx(path)
            except ImportError:
                messagebox.showerror(
                    "Import failed",
                    "Reading Word files needs the python-docx package.\n\n"
                    "Install it with:  pip install python-docx")
                return
            except Exception as exc:
                messagebox.showerror("Import failed", f"Could not read Word file.\n\n{exc}")
                return
        else:
            try:
                with open(path, "r", encoding="utf-8-sig") as fh:
                    content = fh.read()
            except UnicodeDecodeError:
                try:
                    with open(path, "r", encoding="cp1252") as fh:
                        content = fh.read()
                except (OSError, UnicodeDecodeError) as exc:
                    messagebox.showerror(
                        "Import failed",
                        "The file encoding could not be read. Please save it "
                        f"as UTF-8 and try again.\n\n({exc})")
                    return
            except OSError as exc:
                messagebox.showerror("Import failed", str(exc))
                return

        self._remember_for_undo(self.original_box.get("1.0", "end-1c"))
        self.reject()
        self.original_box.delete("1.0", "end")
        self.original_box.insert("1.0", content)
        self._refresh_status(f"imported {os.path.basename(path)}")

    def import_file(self):
        """Open a standard file dialogue and load the selected document."""
        path = filedialog.askopenfilename(
            title="Import text",
            filetypes=[("Text, Markdown and Word", "*.txt *.md *.docx"),
                       ("All files", "*.*")])
        if path:
            self._load_file_path(path)
```
