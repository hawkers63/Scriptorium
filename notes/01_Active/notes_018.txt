Concurrency model

  Backend work, Ollama Detect, the named restore-event watcher, and
  pystray.Icon.run each run on daemon threads. Every path that touches Tk
  from those threads goes through after(0) (Scriptorium._post_to_ui, or

  not checked, and a failed create-event handle would busy-spin the restore
  listener and flood the Tk queue with _bring_to_front callbacks.

 MODERATE - Bug 2. Win32 mutex and restore-event handles are not checked
------------------------------------------------------------------------------
 File:    scriptorium.py
 Functions / methods:
  _claim_single_instance         lines 158–168
  _start_restore_listener        lines 2403–2425
  _watch (inner)                 lines 2413–2423
  main                           lines 2535–2540

 Root cause
  CreateMutexW and CreateEventW results are stored and used without
  testing for a NULL handle, and WaitForSingleObject's return is ignored.

  _claim_single_instance 167–168:
      _mutex_handle = kernel32.CreateMutexW(None, False, _MUTEX_NAME)
      return ctypes.get_last_error() != _ERROR_ALREADY_EXISTS
  If CreateMutexW fails (NULL handle, last error e.g. 8
  ERROR_NOT_ENOUGH_MEMORY or 5 ERROR_ACCESS_DENIED), last error is not
  183, so the function returns True. main() proceeds as the unique
  instance. Single-instance protection is silently off.

  _start_restore_listener 2411, 2414–2418:
      self._restore_event = kernel32.CreateEventW(...)
      while True:
          kernel32.WaitForSingleObject(self._restore_event, _INFINITE)
          kernel32.ResetEvent(self._restore_event)
          self._post_to_ui(self._bring_to_front)
  If CreateEventW returns NULL, WaitForSingleObject(NULL, INFINITE)
  returns WAIT_FAILED immediately. The loop never blocks, ResetEvent
  fails, and _post_to_ui queues _bring_to_front on every iteration. That
  is a daemon-thread busy-spin plus a flood of Tk callbacks (raise,
  focus, and — if a tray icon exists — icon.stop()).

 Deadlock freedom (happy path)
  The mutex is used only as a named existence token (bInitialOwner=False,
  never waited on). The restore event is waited on a side thread; Tk
  never waits on it. No lock-order deadlock. Handles are process-lifetime
  and reclaimed on exit; that is not a leak in practice.

 Reproduction trigger
  Force CreateMutexW / CreateEventW to fail (handle exhaustion, or a
  stricter security policy on Local\ named objects). The mutex case is
  silent dual-instance; the event case is a hot loop after first paint.

 Impact
  Rare, but the failure mode is unbounded CPU and a UI storm, or a
  broken single-instance guarantee, not a clean degrade. ctypes also
  leaves restype at the default c_int (see Suspicion S2).

            .exe run time
------------------------------------------------------------------------------
 File:    C:\Scriptorium\scriptorium.spec
          lines 29–40 (comment), 67–71 (assignment), 101 (EXE kwarg)

 Root cause
  The v2.8 onefile temp-dir fix correctly wants the bootloader to extract
  under %LOCALAPPDATA%\Scriptorium\runtime so a generic %TEMP% sweeper
  cannot delete base_library.zip from under a running process. The spec
  however does:

      runtime_tmpdir = os.path.join(
          os.environ.get("LOCALAPPDATA", os.path.expanduser("~")),
          "Scriptorium", "runtime")

  That Python runs when PyInstaller reads the spec, i.e. on the build
  machine. The string baked into the bootloader is already an absolute
  path such as C:\Users\<builder>\AppData\Local\Scriptorium\runtime.
  PyInstaller's Windows bootloader does call ExpandEnvironmentStringsW
  at run time, but only if the stored string still contains %VAR%
  tokens. After os.environ.get there are none.

  The PyInstaller project documents the working form as a literal
  %LOCALAPPDATA%\... (cmd caret-escaping on the CLI) so expansion
  happens in the bootloader, per user.

 Failure trace
  1. pyinstaller scriptorium.spec on user A's machine.
  2. EXE(runtime_tmpdir=...) stores A's LOCALAPPDATA path.
  3. User B runs Scriptorium.exe, or user A is renamed / the profile
     is on a different drive.
  4. The bootloader tries to create _MEIxxxxxx under A's profile.
  5. Extraction fails or writes into the wrong tree; the process cannot
     start, or a leftover runtime folder accumulates under a stale
     profile.

 Reproduction trigger
  Rebuild the onefile .exe, then run it under a different Windows
  account than the one that built it. Same-user same-machine use (the
  current developer workflow) will not show it.

 Impact
  The documented intent of the v2.8 temp-dir fix is only met for the
  account that built the binary. Portability of dist\Scriptorium.exe is
  broken. This is a packaging logic error, not a runtime crash in the
  .py when run from source.

def normalise_config(cfg):
    """Return a copy of cfg with constrained settings restored to safe values.

    A hand-edited or stale config file can contain an out-of-range enum (an
    old default_mode, an unrecognised backend) or a stringy boolean
    ("false" is truthy under bool()). Left unchecked, that either crashes the
    worker thread with a KeyError or — for "backend" specifically — makes the
    status bar and the actual HTTP dispatch disagree about whether text
    leaves the machine. Free-form fields (the API key, model tags) are left
    untouched.
    """
    clean = dict(cfg)
    choices = {
        "backend": ("anthropic", "ollama"),
        "default_mode": tuple(MODES),
        "default_strength": tuple(STRENGTHS),
        "default_role": tuple(ROLES),
        "default_diff_view": ("Clean", "Inline"),
    }
    for key, allowed in choices.items():
        if clean.get(key) not in allowed:
            clean[key] = DEFAULT_CONFIG[key]

    for key in ("privacy_ack", "protect_placeholders",
                "check_letter_conventions", "import_prompt_shown",
                "minimise_to_tray", "start_with_windows", "start_minimised",
                "always_on_top"):
        value = clean.get(key, DEFAULT_CONFIG[key])
        if isinstance(value, str):
            clean[key] = value.strip().lower() in ("1", "true", "yes", "on")
        elif not isinstance(value, bool):
            clean[key] = DEFAULT_CONFIG[key]
        else:
            clean[key] = value

    clean = normalise_tone_config(clean)
    return clean

from ctypes import wintypes

_WAIT_OBJECT_0 = 0
_WAIT_FAILED = 0xFFFFFFFF
_EVENT_MODIFY_STATE = 0x0002

def _kernel32():
    """Return kernel32 with HANDLE-safe argtypes (64-bit truncation)."""
    k32 = ctypes.WinDLL("kernel32", use_last_error=True)
    k32.CreateMutexW.argtypes = [wintypes.LPVOID, wintypes.BOOL, wintypes.LPCWSTR]
    k32.CreateMutexW.restype = wintypes.HANDLE
    k32.CreateEventW.argtypes = [wintypes.LPVOID, wintypes.BOOL, wintypes.BOOL,
                                 wintypes.LPCWSTR]
    k32.CreateEventW.restype = wintypes.HANDLE
    k32.OpenEventW.argtypes = [wintypes.DWORD, wintypes.BOOL, wintypes.LPCWSTR]
    k32.OpenEventW.restype = wintypes.HANDLE
    k32.SetEvent.argtypes = [wintypes.HANDLE]
    k32.SetEvent.restype = wintypes.BOOL
    k32.ResetEvent.argtypes = [wintypes.HANDLE]
    k32.ResetEvent.restype = wintypes.BOOL
    k32.WaitForSingleObject.argtypes = [wintypes.HANDLE, wintypes.DWORD]
    k32.WaitForSingleObject.restype = wintypes.DWORD
    k32.CloseHandle.argtypes = [wintypes.HANDLE]
    k32.CloseHandle.restype = wintypes.BOOL
    return k32


def _claim_single_instance():
    """Return True if this process now owns the single-instance mutex.

    False means another Scriptorium is already running, or the mutex could
    not be created. A NULL handle is treated as failure (do not start a
    second 'unique' copy with no lock), not as success.
    """
    global _mutex_handle
    kernel32 = _kernel32()
    handle = kernel32.CreateMutexW(None, False, _MUTEX_NAME)
    if not handle:
        return False
    _mutex_handle = handle
    return ctypes.get_last_error() != _ERROR_ALREADY_EXISTS


def _start_restore_listener(self):
    """Watch the named restore event so a second launch can wake us up.

    Runs on a daemon thread; the actual window operations happen back on
    the Tk thread via _post_to_ui(), same as every other worker-thread
    callback in this app. A failed CreateEventW is logged and the watcher
    is not started — a tight WaitForSingleObject(NULL) loop would otherwise
    spin the CPU and flood Tk with _bring_to_front callbacks.
    """
    kernel32 = _kernel32()
    handle = kernel32.CreateEventW(None, True, False, _RESTORE_EVENT_NAME)
    if not handle:
        print("[warning] could not create the restore event; a second "
              "launch will not bring this window to the front")
        self._restore_event = None
        return
    self._restore_event = handle

    def _watch():
        while True:
            rc = kernel32.WaitForSingleObject(self._restore_event, _INFINITE)
            if rc != _WAIT_OBJECT_0:
                # WAIT_FAILED or a closed handle — do not busy-spin.
                break
            kernel32.ResetEvent(self._restore_event)
            try:
                self._post_to_ui(self._bring_to_front)
            except Exception:
                pass

    threading.Thread(target=_watch, daemon=True).start()
