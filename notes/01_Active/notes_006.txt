1. Named toolbar presets  (lead proposal)
-----------------------------------------
Why
    Role, mode, strength and tone already stack independently. A letter-
    focused user still has to set four knobs for every job. A small
    named-preset menu that *fills those existing knobs* is the highest-
    value change that does not touch the backend, the JSON schema, or
    config. After apply, the knobs stay independently editable.

    notes_002 and notes_005 already asked for this. The design below is
    remapped to v1.5 line numbers and uses the *current* role labels
    (Executive, Client Relations, Software Developer — not the longer
    names from notes_002).

Do not persist the last-used preset in scriptorium_config.json on this
pass. That keeps the change local to the toolbar and avoids a config-
schema bump.

def apply_preset(app, name):
    """Populate the existing toolbar knobs from a named preset.

    Knobs remain independently editable afterwards. '(none)' is a no-op
    so the user can park the menu without resetting Mode/Strength/Role/Tone.
    """
    spec = PRESETS.get(name)
    if not spec:
        return
    app.mode_var.set(spec["mode"])
    app.strength_var.set(spec["strength"])
    app.role_var.set(spec["role"])
    app.tone_var.set(spec["tone"])

3. Request-generation counter  (companion state fix)
----------------------------------------------------
Why
    process() (line 861) snapshots _processing_source and refuses a
    second Process while busy=True. That is not enough:

      * Reject / Undo / Clear / Import while a worker is in flight
        clear last_result, then _on_success still lands and puts the
        stale revision back.
      * copy_revision (line 979) never calls _revision_is_stale, unlike
        accept (line 960) and export_file (line 1020).

    A monotonic _request_id is the smallest fix. This is notes_005
    Fix 1, remapped to v1.5. It is a state-consistency patch, not a
    rewrite; include it with the two UI items so Accept/Copy cannot
    apply a previous revision after the user has already moved on.

4. Deliberately deferred
------------------------
These are sound, but they should not ride in the same patch:

  * Extract SettingsDialog (lines 570–678) or the prompt tables
    (MODE_INSTRUCTIONS / ROLE_INSTRUCTIONS / build_system_prompt,
    lines 163–245) to a sibling module. First modular cut, behaviour
    unchanged. Worth doing *after* the toolbar has settled, otherwise
    two files move at once.
  * Appearance toggle (ctk.set_appearance_mode("dark") is hardcoded at
    line 690). One Settings checkbox; needs the revised_box colours
    (#1d1e1e / #dce4ee at lines 771–774) to follow the theme, so it is
    not quite a one-liner.
  * Keyboard shortcuts for Accept / Reject / Undo. Process already has
    Ctrl+Enter. Fine as a follow-up polish.
  * Session history (notes_005). Depends on the request-id work above.
  * Tightening mask_placeholders so Markdown links and [1] citations
    are not treated as placeholders. 
  * load_config (line 141): cfg.update(json.load(...)) will raise
    TypeError if the file decodes to a non-dict. Catch TypeError next
    to JSONDecodeError when someone is already touching config. Do not
    rewrite the file on a corrupt load — that is how an API key gets
    lost (notes_005).
  * Three alternatives in one request. notes_001 correctly put this
    last: it changes the response schema, the pane state, latency and
    token cost.
